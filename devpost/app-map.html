What it is

Fair Lease checks a Spanish rental contract. One Next.js page does almost everything in the browser. The only server code is one route that asks Claude to extract and quote. Plain TypeScript then checks every quote against the text, picks the law version from the signing date and runs 18 hand-checked rules that give the verdicts. The three samples carry a recorded extraction, so they skip the Claude call but run everything after it for real.

Reference route through the code

A reference route, not a guided tour: the learner delegated the wrap-up, so nobody walked these stops live.

  1. The button. components/FairLease.tsx, search const checkLive. It validates the input (lib/validate.ts), anonymises it (anonymize in lib/anonymize.ts), POSTs to /api/extract and ticks the real checking steps.
    Server side of that call

    app/api/extract/route.ts → runExtraction in lib/extract.ts (input bounds, daily limit, one retry, schema validation) → callClaude in lib/claude.ts (structured output from the zod schema in lib/extraction.ts; the prompt is in lib/prompt.ts).

  2. The kernel. lib/analyze.ts, function analyze: verifyQuotes (lib/quotes.ts) drops any quote not literally in the text, resolveLaw (lib/law.ts) picks 2019 / May 2023 / Oct 2026 from the signing date, and runRules (lib/rules/index.ts) runs every rule and merges findings on the same clause.
  3. One rule to the screen. lib/rules/fl02-extra-guarantees.ts, fl02.evaluate, adds the deposit above one month to the extra guarantees and compares with the cap (2 months, or 1). Its finding is drawn by components/result/FindingNote.tsx: verdict chip, number, law quote with BOE link, and “Ask for this instead”.

A practice to reuse

Write the expected result before the model runs, then test the model's output against the verdicts, not against your fixture's exact rows.

The three contracts' expected results existed before any code. The rules were built against hand-made fixtures until they matched exactly (tests/gold.test.ts, tests/gold-law.test.ts). When real Claude output arrived, the same expectations caught real issues:

  • Haiku split clause SEGUNDA into two sentences and FL-05 fired twice. Fixed by merging findings on the same clause, with a robustness test in tests/gold.test.ts.
  • Opus quoted clause NOVENA as one passage and the “first six months” fine note vanished. Fixed in lib/rules/fl07-early-exit.ts.

tests/recorded.test.ts now checks what matters: every quote found (0 hidden) and the same not-enforceable and worth-checking verdicts. On another project, the same move works whenever an LLM feeds deterministic code. Fix the expected outputs first, let the model only extract, verify its citations in code, and assert on decisions rather than on wording.

Run it again

npm install then npm run dev and open http://localhost:3000. The samples work without a key. Checks: npm test, npm run build, npm run check:ui. Real API checks: npm run try-live, or FL_REAL_LIVE=1 npx playwright test e2e/real-live.spec.ts (a few cents).
